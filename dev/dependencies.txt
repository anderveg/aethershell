# Dépendances du shell, du compositeur et de ce que le panneau pilote.
#
# Un binaire par ligne, contrôlé par `command -v`. Les commentaires sont libres.
# Les portées remplacent les trois anciens fichiers de dépendances :
#
#   #: commun   → tous les postes et toutes les distributions
#   #: laptop   → PC portable seulement (batterie / châssis portable)
#   #: desktop  → PC fixe / tour seulement
#   #: arch     → Arch Linux seulement
#   #: fedora   → Fedora seulement
#   #: debian   → Debian / Ubuntu seulement
#
# Une ligne hors de toute portée est ignorée : un ajout en tête de fichier ne
# peut donc pas se retrouver silencieusement dans la liste.

#: commun
# git et curl : ce que l'installateur en une ligne réclame avant tout le reste
#   curl -fsSL .../install.sh | sh

# Visualiseur audio : moteur pwscope compilé localement (C + PipeWire) et,
# pour le mode barres, cava. `cc`, `make` et `pkg-config` ne servent qu'à la
# compilation ; les en-têtes pipewire se contrôlent par pkg-config, pas par
# command -v (scripts/pwscope_make.sh le fait).
cc
make
pkg-config
# Rust : le backend as-core est compilé au déploiement. Sans cargo, install.sh
# dépose le binaire du dépôt même s'il est plus ancien que les sources — donc
# les correctifs Rust restent dormants (cas réel : interrupteur de limite de
# charge corrigé dans le code, jamais compilé sur un portable sans Rust).
cargo
# Liaison de as-core : ring et ort sont du C++, et la base SQLite est liée
# statiquement dans le binaire. Fedora les sépare de gcc/sqlite (paquets
# gcc-c++ et sqlite-devel) ; Arch et Debian les incluent. `c++` couvre le
# premier ; le second est vérifié par install.sh au moment de compiler.
c++
cava
